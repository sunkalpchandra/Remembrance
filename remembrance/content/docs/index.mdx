## Introduction

We're Reteena, an R&D lab focused on progressive challenges around
Alzheimer's disease. **Remembrance** is our cognitive care companion: it
holds natural, therapeutic conversations with patients and quietly turns
what they share into a persistent personal memory system — so no matter
how much time passes, their memories are never lost.

Every conversation flows through a memory pipeline: the model decides
what's worth keeping, saves it through a tool call, and later retrieves
it to ground new conversations. Memories live in Postgres (always) and
in [Mem0](https://mem0.ai) for semantic search (when configured), and
they surface across the product — the memory graph, the repository
editor, the printable Memory Book, and personalized conversation
starters.

## The pieces

**Chat** — the heart of the app. The model streams its replies and calls
two tools as it goes: `save_user_info` to store something the user
shared, and `retrieve_user_info` to pull relevant context before
answering. Chat works over two interchangeable transports:

- **Serverless** (default): the built-in `/api/chat` route streams over
  SSE. No extra processes — this is how the Vercel deployment works.
- **Realtime backend**: a Koa + Socket.IO process (`npm run server`)
  with the same event contract, used when `NEXT_PUBLIC_BACKEND_URL` is
  set. It additionally syncs memories into Neo4j.

**Memory graph** — a force-directed view of everything remembered.
Nodes are classified (family, places, events, health, …) and labeled by
a fast model; related memories are chained by shared people and places.

**Repository** — a Notion-style editor (Novel/tiptap) over your
memories, organized in a folder tree, synced to the database so the
graph stays current.

**Caregiver dashboard** — caregivers manage patient accounts, write
notes that flow into the patient's memory store, and see an activity
feed of patient engagement. Caregivers accept a HIPAA agreement before
any of this unlocks.

**Memory Book** — a print-ready book of every saved memory, grouped by
month. Printing to PDF is the export path.

## Accounts and roles

Authentication is [Clerk](https://clerk.com). At onboarding every user
picks a role — **individual**, **patient**, or **caregiver** — which the
middleware uses to route them: caregivers land on the dashboard,
patients and individuals in chat. A Clerk webhook keeps the local
`users` table in sync.
